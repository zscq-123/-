# 测试与评测记录

本页区分可重复的软件验证与仍需机构、线路和人员参与的业务验收。当前测试对象为虚构数据原型，不能据此声称达到真实试点准入条件。

## 可复现方法

1. 运行 `./scripts/check.sh`：后端自动化测试、SQLite 备份恢复测试、前端类型与生产构建。
2. 在新的测试数据库启动后端，设置 `RATE_LIMIT_PER_MINUTE=10000`。
3. 运行 `scripts/api_smoke.py` 与 `scripts/api_boundaries.py`，检查完整闭环、角色隔离、授权材料、知识与名录生命周期、电话异常和关键字段冲突。
4. 运行 `scripts/evaluate.py`，保存 `artifacts/local/evaluation.json`。报告记录代码提交、工作树状态、样本哈希和逐例结果。
5. 若要证明纯提交版本，应先提交代码，再在干净工作树复跑；不得把开发中报告冒充最终发布验收。

## 自动化评测口径

固定集 `tests/fixtures/intake-synthetic-v1.json` 包含 100 条虚构记录，由 `scripts/generate_fixtures.py` 按 4 种句式生成，覆盖劳动争议、婚姻家庭和交通事故，包含 5 个地点及多组日期。共有事项、地点、日期、诉求 400 个字段标签。字段标签由模板生成，未经过独立专业标注。

字段比较中，事项、地点、日期使用完全匹配；诉求检查原标签是否包含在提取结果中，允许额外前缀与标点。流程比较检查最终状态是否为 `awaiting_confirmation`。引用比较仅检查标题、来源 URL、版本与定位字段齐备；模拟 URL 使用保留域名，不表示真实来源有效或法律内容正确。

另做 50 次“用户主动要求人工”的 HTTP 状态转换，检查 `handed_off`。这些测试没有真实电话、音频、转接设备或工作人员接听，不计为方案“指定环境至少 50 次人工接管”的业务成功率。

## 原方案指标的验收差距

| 指标或退出条件 | 本原型能测什么 | 仍需什么 |
| --- | --- | --- |
| 必要字段准确率 ≥90% | 100 条固定模板、400 字段匹配 | 独立多样化脱敏样本与人工标注 |
| 智能体路由准确率 ≥90% | 固定类别的规则路由与风险测试 | 业务专家标注路径和复杂案例 |
| 来源可定位 100% | 模拟引用元数据齐全 | 真实来源、有效版本和业务审核 |
| 越权工具调用为 0 | 白名单、角色与隔离自动化测试 | 全量测试日志审查和试点安全评审 |
| 人工接管成功率 ≥95% | 50 次 HTTP 队列状态转换 | 授权电话环境、真实坐席和故障测量 |
| 摘要可用性 ≥80% | 结构化摘要与版本确认 | 工作人员盲评及修改量统计 |
| 登记效率降低 20% | 可记录软件运行耗时 | 同条件人工对照实验和遗漏率 |
| 受控试点准入 | 软件原型与重复演示 | 业务确认、真实线路、机构授权和安全审查 |

八周需求与开发成果映射由 [需求追踪](REQUIREMENTS.md) 维护。缺陷关闭记录、实际测得数字和未通过项必须以报告为准，不能仅依据预期目标填写。

## 独立检查发现与修复

2026-11-18 的独立 HTTP 检查发现成年年龄被未成年人正则误匹配、自然语言更正仍保留旧摘要两项问题，并指出单轮智能体步骤可能超过限额。后端补充年龄数字边界、自然语言更正的冲突记录与转人工、单轮步骤预算预留。74 项后端测试和独立 HTTP 边界脚本复测通过，原失败场景保留在回归脚本中。

逐例模板报告保存在本地 `artifacts/local/evaluation-qa-20261118-stage4.json`（Git 忽略，不含真实咨询）。报告标明当前代码提交及开发工作树状态；发布时应按最终提交重跑并保全报告。

## 触屏端验收项目

使用 Chromium 触摸模拟验证 1280×800 横屏、390px 窄屏。实测首页两条入口、全程点选、返回修改、带来源核对、确认提交、后台查询编号与工单关闭、电话转写事件模拟、手动清屏、30 秒结束回屏和 3 分钟无操作清屏。验证了语音服务单独授权，以及识别能力不可用时转文字填写。现场触摸屏、麦克风识别准确率和真人辅助仍待机构实测。
